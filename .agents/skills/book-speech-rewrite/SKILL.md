# Book TTS 朗读稿整理

Book TTS 项目目录：`/Users/liguoyang/Documents/code/book-tts`。以下命令都在该目录执行。

## 参数

- **书籍**：书籍 ID。用户没给时，运行 `.venv/bin/python -m app.speech_io list` 列出书籍，让用户选择。
- **风格**：`faithful`（贴近原文：只清理注释、符号等，保留原文表达）或 `narrated`（讲述改写：清理后改写成主讲人的讲述口吻）。用户没说明时先询问，不要自行决定。

## 流程

1. **导出**：
   ```bash
   .venv/bin/python -m app.speech_io export --book <书籍ID> --style <faithful|narrated>
   ```
   输出会给出导出目录。如果提示目录已存在，说明之前整理过一部分：直接在该目录继续，`speech_text` 为 `null` 的分段就是还没整理的。

2. **阅读规则**：完整阅读导出目录中的 `rules.md`，整理时严格遵守。

3. **逐章整理**：按 `manifest.json` 中 `chapters` 的顺序处理 `chapters/` 下的每个文件。
   - 先通读整章所有分段的 `text`，了解上下文。整章的分段在书中是连续的，被注释或分段边界截断的句子按规则在句子开头所在的分段补全。
   - **每 5 段为一组写入 `speech_text`**。每组动笔前重新阅读 `rules.md` 的全部规则，讲述改写风格下尤其是讲述手法（设问、口语衔接）和保留原话这两条，保证整章从头到尾都按同样的标准执行，不要越写越简略。
   - 整章写完后做一遍自查：逐段对照原文，原文有转折、因果或关键结论而朗读稿没有用讲述手法引出的，补上；人物的关键原话被改成了转述的，恢复为直接引语；数字写成中文读法。
   - 只修改 `speech_text` 字段；不要增加、删除、合并、拆分或调换分段，不要改动其他字段。
   - 整段都是注释等不适合朗读的内容时，`speech_text` 写空字符串 `""`。
   - 自然段之间用一个空行（`\n\n`）分隔。
   - 朗读稿由你亲自阅读和改写；不要编写调用其他模型或 API 的脚本来代替，也不要用正则批量替换来“整理”。

4. **每章检查**：写完一章立即运行
   ```bash
   .venv/bin/python -m app.speech_io check --dir <导出目录> --chapter <章节文件名>
   ```
   有问题就修改后重新检查，直到通过再处理下一章。报错中的“分段 N”对应章节文件里 `segment_index` 为 N 的分段。常见问题：
   - “朗读稿与原文内容对不上”：该分段写入了其他分段的内容，或内容与原文偏离过大，重新对照该分段原文整理。
   - “还没有整理”：该分段的 `speech_text` 仍是 `null`。
   - “还有阿拉伯数字”：把报错位置的数字改成中文读法，年份按“一九三二年”的方式逐位读。

5. **导入**：全部章节检查通过后运行
   ```bash
   .venv/bin/python -m app.speech_io import --dir <导出目录>
   ```
   通过校验的章节写入朗读稿，未通过的章节会列出原因且不写入。

6. **汇报**：告诉用户导入了哪些章节、哪些未通过及原因。提醒用户：已生成过语音的章节需要在 Book TTS 中「重新生成本章语音」才会使用新的朗读稿。

## 书较长时

一次对话不必整理完整本书。每完成若干章就先运行检查；中途停止后，下次在同一导出目录继续即可，已写入的结果不会丢失。可以对已全部检查通过的章节先运行导入，导入只会写入通过校验的章节。
